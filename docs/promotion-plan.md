# PostEx 30-day promotion plan

**Campaign line:** Give every study its own visual identity.<br>
**Product formula:** Paper × Inspiration × Conference → Editable, traceable poster<br>
**Plan date:** 2026-08-10<br>
**Mode:** Organic-first launch; no paid amplification until repository conversion is measured.

## 1. Outcome and operating targets

The campaign is designed to turn qualified attention into product trials, stars, conference requests, and contributions. Stars are a useful bookmark and distribution signal, but they are not the only success measure.

| Day 30 target | Base | Strong |
|---|---:|---:|
| GitHub stars | 100 | 200 |
| Qualified repository visitors | 1,500 | 3,000 |
| Full clones or verified installs | 50 | 100 |
| Actionable user feedback items | 15 | 30 |
| User or maintainer showcase cases | 5 | 10 |
| Conference Pack requests | 20 | 40 |
| External contributors | 2 | 5 |

These are planning targets, not forecasts. The primary conversion metric is:

```text
star conversion = new stars / unique repository visitors
```

Track repository visitors, referrers, popular content, and clones through GitHub Insights → Traffic. GitHub retains this traffic view for a rolling 14-day window, so capture a weekly snapshot.

## 2. Positioning

### Primary promise

> Turn a paper, an inspiration palette, and a target conference into an editable, evidence-linked academic poster.

### Message hierarchy

1. **Inspiration earns attention.** A visual idea becomes Palette DNA with semantic roles, usage ratios, component behavior, and print-aware contrast.
2. **Editable output earns trial.** PPTX remains the canonical artifact; PDF, PNG, evidence, and design rationale accompany it.
3. **Conference Intelligence earns relevance.** Annual packs distinguish organizer facts from independent PostEx recommendations.
4. **Trusted Export earns confidence.** Evidence, approvals, rights records, preflight, and hashes remain inspectable.

PostEx should not lead with “another AI paper-to-poster generator.” The defensible position is a visual-identity system with conference-aware constraints and an explicit trust boundary.

## 3. Priority audiences

| Audience | Immediate need | Best proof | Primary action |
|---|---|---|---|
| Researchers with an accepted poster | Finish a compliant, editable poster | Conference Pack + PPTX | Try the golden demo |
| Medical and life-science teams | Protect scientific fidelity and privacy | Evidence links + medical preflight | Request a conference |
| AI/CS researchers | Produce a distinctive poster quickly | CVPR case + Visual Signature | Star and test |
| Codex and Claude Code users | Reuse an agent-friendly workflow | CLI and approval gates | Clone and report feedback |
| Scientific designers | Build identities without template sameness | Palette DNA + rationale | Submit an inspiration |
| Open-source contributors | Make a bounded contribution | Pack schema + validator | Add or verify a pack |

## 4. Launch-readiness gate

Do not begin the broad launch until the following items are complete or explicitly marked as alpha limitations:

- [x] First-screen value proposition and product formula
- [x] One-paper/three-identities hero image
- [x] 35-card Genshin collection preview
- [x] Genshin Study Identity campaign registry and rights language
- [x] Seven Conference Packs with explicit verification state
- [x] Golden paper, editable PPTX, PDF, PNG, evidence, and approval records
- [ ] 20–30 second product demonstration
- [ ] 1280×640 repository social preview
- [ ] Published `v0.5.0a1` GitHub Release
- [ ] One-command, no-API-key golden demo
- [ ] Lightweight public gallery or GitHub Pages site
- [ ] GitHub Discussions with Showcase, Q&A, and Conference Requests
- [ ] `Request a Conference Pack` issue form
- [ ] Core installation separated from optional large palette media

The unchecked items are conversion work, not optional polish.

## 5. Content system

Use a stable editorial mix so each feature creates repeated, recognizable stories.

| Pillar | Share | Recurring format |
|---|---:|---|
| Inspiration palettes | 40% | Study Identity and palette breakdowns |
| One paper, multiple identities | 25% | Side-by-side carousel or short video |
| Conference Intelligence | 20% | Conference × Inspiration and rule explainers |
| Trust engineering | 10% | Provenance, approval, privacy, and preflight cases |
| Builder/community updates | 5% | Release notes, requests, and contributor stories |

### Core series

- **Study Identity:** one source of inspiration, one Palette DNA, one audited poster.
- **One Paper, Three Identities:** Academic Safe, Balanced Fusion, and Visual Signature.
- **Seven Regions, One Paper:** one research source expressed through seven cataloged Genshin-inspired identities.
- **Conference × Inspiration:** the conference defines constraints; the inspiration defines identity.
- **Official or PostEx?:** a short comparison of sourced organizer facts, PostEx recommendations, and unknown fields.
- **Inside Trusted Export:** one concrete check per post, shown through a real manifest or preflight finding.

## 6. Thirty-day execution

### Days 1–7: conversion and seed users

**Objective:** make the repository understandable and test the workflow before broad distribution.

- Complete the launch-readiness gate.
- Recruit 20–30 researchers and scientific-tool users through direct, personal outreach.
- Ask each tester to complete one bounded task: understand the first screen, run the golden demo, open the PPTX, or request a conference.
- Record friction without asking for a star first.
- Publish the Paimon hero case, Varka showcase, and CVPR Conference Pack explainer.

**Exit criteria:** five completed trials, three actionable fixes, and no unresolved blocker in the quick-start path.

### Days 8–14: public launch

**Objective:** create the first concentrated wave of qualified traffic.

- Publish the primary launch video and repository link on X and LinkedIn.
- Publish a Chinese case-study version on Zhihu, Xiaohongshu, Bilibili, and relevant research groups.
- Submit a runnable Show HN only when the demo works without a signup or email gate.
- Share educational case studies—not identical advertisements—in relevant Reddit communities after checking each community's current self-promotion rules.
- Answer every substantive question within one day.

**Primary asset:** One Paper, Three Identities.<br>
**Primary CTA:** Try the synthetic paper demo; star the repository to follow the next Conference Pack.

### Days 15–21: medical conference focus

**Objective:** establish a narrow professional wedge instead of competing only on generic generation.

- Publish AACR privacy-marker and e-poster checks.
- Publish ASCO commercial-content and logo guardrails.
- Explain verified versus partially verified packs using ESMO, RSNA, and AHA.
- Invite oncology, bioinformatics, radiology, and cardiovascular researchers to request missing conferences.
- Turn one accepted request into a public, provenance-backed contribution task.

### Days 22–30: community loop

**Objective:** convert one-time launch attention into recurring releases.

- Publish the first community-requested or community-contributed pack.
- Launch the Seven Regions, One Paper sequence only for identities with audited poster outputs.
- Open a palette-inspiration submission thread.
- Publish a user gallery and a transparent “what we learned” update.
- Select the next four weeks of packs and identity studies from observed requests, not an arbitrary catalog target.

## 7. Channel roles

| Channel | Role | Best artifact |
|---|---|---|
| Direct lab/researcher outreach | Highest-quality feedback | Conference-specific demo |
| X | Fast visual discovery | 20-second comparison video |
| LinkedIn | Professional credibility | Conference and trust case study |
| Zhihu | Long-form Chinese discovery | Technical product narrative |
| Xiaohongshu | Visual researcher reach | Palette/poster carousel |
| Bilibili | Demonstrated workflow | 3–6 minute walkthrough |
| Hacker News | Developer feedback and burst traffic | Runnable Show HN |
| Reddit | Domain discussion | Educational before/after case |
| Product Hunt | Broader product launch | Use only after a public demo exists |
| GitHub topics/awesome lists | Long-tail discovery | Clear metadata and contribution value |

Never coordinate votes, exchange stars, or ask a community to inflate ranking. Calls to action should be tied to utility: try, bookmark, request, or contribute.

## 8. Conversion calls to action

Use one main action per asset.

- Palette content: **Pick a palette and see the poster.**
- Conference content: **Request your conference.**
- Technical content: **Inspect the schema and validator.**
- Launch content: **Try the demo. Star PostEx if you want to follow the next Conference Pack.**
- Contributor content: **Verify one requirement or add one bounded pack.**

## 9. Measurement and decisions

Capture a weekly scorecard:

| Metric | Source | Decision it informs |
|---|---|---|
| Unique visitors and referrers | GitHub Traffic | Which channels bring qualified attention |
| Stars per visitor | Traffic + star delta | Repository/message conversion |
| Clones and release downloads | GitHub | Trial intent |
| Demo completions | Demo telemetry or manual cohort | Setup friction |
| Conference requests | Issues/Discussions | Pack priority |
| Showcase submissions | Discussions | User value and social proof |
| External contributors | GitHub | Community health |

Interpret common patterns:

- High visits, low stars: simplify the first screen or sharpen differentiation.
- High stars, low clones: reduce setup and package size.
- High clones, low completion: improve the golden path and environment checks.
- Strong palette shares, weak conference requests: pair visual content with a concrete meeting workflow.
- Strong medical requests: prioritize verified packs and Research Archetypes over catalog breadth.

## 10. Growth loop

```text
inspiration card attracts attention
→ audited poster proves the transformation
→ golden demo enables trial
→ Conference Intelligence creates immediate relevance
→ Trusted Export creates confidence
→ user requests a conference or submits an inspiration
→ the contribution becomes the next release and story
```

Every new palette identity, verified conference, and user case should create a useful product increment and a new reason to discover PostEx.
